# Hard problems `challenges`

The spikes solved most questions. These problems are still hard. The list starts with the largest. Labels: "verified", "inferred", or "a guess".

| Name | Problem | Why it is hard | Best option now |
|---|---|---|---|
| `challenges.fail_loud` | One uncaught error in one widget stops the whole host, and so every widget (verified). | DSH installs `installFailLoud` for each profile. Cordis cannot catch an error from a `setTimeout` callback. | The runtime owns timers and wraps each handler. The host error handler quarantines the widget that the stack names (option F). Electron main restarts a dead host. Later: agent code in a separate process. (`options.isolation`) |
| `challenges.agent_code` | Code that an agent writes runs in the host process with full Node rights. | It can read files, make any network call, and block the event loop. A CPU loop blocks every widget (inferred). | Data widgets need no agent code. Logic widgets need approval. Later: a `utilityProcess` with only fetch and state. |
| `challenges.unjoined` | The spikes proved the parts one at a time. They were not joined (reviewer, verified). | Each part used its own CRUD descriptor and its own copy of the action rules. | The integration spike (`spikes.integration`). |
| `challenges.code_in_bundle` | A logic widget bundle can run agent text also without handler code: `!!js` in its patch file, and pnpm dependencies (verified). | The plugin manager installs what it gets. | Lint each bundle before install. Data widgets need no bundle. |
| `challenges.replace` | A replace removes the old widget first. A failed install then loses the user's widget (inferred). | The plugin manager refuses a second install of one name. | Check first, or keep the old bundle until the new one applies. |
| `challenges.identity` | Any name gets a token, and each handshake gets a new id (verified). | No auth in v1 by choice | No per-agent rules in v1. A `locked` flag and a trash protect the user's widgets. |
| `challenges.write_rate` | Every write rewrites the whole `widgets.json` in one queue: about 100 writes each second. 20 widgets with one write each took 217 ms at the median (verified). | Timer widgets write often. | One record for each slug, or the sqlite backend. Coalesce writes of window positions. |
| `challenges.push_to_agent` | MCP clients do not show change notifications to the model today (inferred from docs). | The protocol supports it. The clients do not use it yet. | The change feed `widget_changes({since})`, and a count of pending changes in each tool result. |
| `challenges.port_squat` | Another process can bind `0.0.0.0` on our fixed port while we bind `127.0.0.1` (verified on macOS). An agent can then talk to the wrong server. | No auth in v1 by choice | A server nonce in the port file that the agent checks (inferred). |
| `challenges.react18_shadcn` | The shadcn example breaks on React 18. The shadcn ecosystem moves to React 19. | Radix needs `forwardRef` on React 18. | Our own forked set with patched components. A later move to React 19 needs the same in DSH. |
| `challenges.openui_internals` | The external refresh uses an action plan shape that OpenUI does not export (verified). | A minor OpenUI release can change it. | Pin react-lang 1.0.1 and keep a test that fails when it changes. |
| `challenges.eventsource_stop` | A browser `EventSource` stops for good on an answer that is not 200 (inferred from the spec). | A 404 during boot or after a widget reloads ends the stream. | The shell reopens the stream itself with backoff. |
| `challenges.electron_launch` | After a crash, later launches of this Electron build stopped at a macOS "reopen windows?" dialog (verified by two agents). | It can also block the real app in a test. | Launch tests with `-ApplePersistenceIgnoreState YES`. |
| `challenges.memory` | Each widget window is a renderer process of about 20.6 MB. 20 widgets use about 583 MB (verified). | A shared renderer uses about 1.8 MB for each widget, but one crash closes all of them (verified). | Separate windows by default. A user setting for a shared renderer. |
| `challenges.quit_hang` | After a renderer crash, closing the windows and then calling `app.exit` hung Electron main in about 5 of 12 runs. It ignored SIGTERM (verified, cause unknown). | The user cannot quit the app. | Call `app.exit` with no window teardown first (4 of 4 clean). Test the DSH quit path after a widget crash. |
| `challenges.panel_spaces` | A panel window ignores `setVisibleOnAllWorkspaces(false)` (verified). | A setting "main desktop only" cannot work on a panel window. | Use a normal window for such a widget, or drop the setting. |
| `challenges.hidden_alert` | With no Dock icon, the macOS "reopen windows?" alert after a crash can block the launch where the user cannot see it (inferred). | The app seems to not start. | Launch with `-ApplePersistenceIgnoreState YES`, or clear the saved state at quit. |
| `challenges.link_install` | A `link:` install points at the agent's workspace folder. If the agent moves it, the widget breaks (inferred). | DSH installs from the given path. | Copy the package into a folder that the profile owns before the install. |
| `challenges.pnpm_in_app` | The plugin manager runs pnpm. The packaged desktop app must ship pnpm (not checked). | DSH desktop says that it uses bundled pnpm (read in `docs/architecture.md`). | Check in the packaged app before agents install there. |
