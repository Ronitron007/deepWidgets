# Ephemeral agent surfaces

29 November 2026

The agent review proposes a local collaboration milestone before the hosted connector. The [product direction](../../specs/product-direction.md) and [unified architecture verdict](future-of-ui-verdict.md) record the settled operator decision: drop OpenUI (`@openuidev/react-lang`), upgrade unconditionally to React 19, ship `@deepwidgets/shell/ui/*` + `@deepwidgets/widget-kit` on Vercel UI SDK (`@ui-sdk/core` + `@ui-sdk/react`), and compile ephemeral `.tsx` surfaces via in-memory `esbuild.transform` over a pre-bundled ESM importmap rather than keeping the OpenUI catalog renderer proposed in the table below. The lease, `decisionId` receipt lookup, renderer `requestId`, and trusted desktop confirmation mechanics below remain active requirements.

## The first workflow

An agent reviewing a change can open a small native desktop window with the proposed edits, their consequences, and a short list of choices. The person selects the edits to keep and submits the decision from deepWidgets. The result returns to the agent's current task. The surface closes after the result is recorded. If the person wants the surface as an ongoing widget, they can pin it explicitly.

This tests a desktop-specific benefit early. The agent can show live structured information and ask the person for input without moving the work into chat or having each agent app build its own widget renderer. Persistent local widgets still matter. Hosted connectors extend the same model to other devices and apps once the PC can enforce and revoke their grants. [Hosted connector design](architecture.md#4-architecture-for-agents-anywhere)

## The proposed decision and lifetime model

1. **Open.** A local MCP client asks for a supported surface. The desktop validates the declarative content, associates a lease with the calling principal, and records a decision request before showing it. Surface identity, decision identity, and durable mutation identity serve different purposes. Opening twice with the same operation should have a defined outcome.
2. **Decide.** The trusted desktop UI presents what the person is being asked to decide, including the affected target. Only its operator interaction may settle an approval. Bind the result to that request and its version, then settle once. A renderer event or a DOM confirmation marker can help present the flow. It carries no approval authority on its own.
3. **Return.** A bounded tool call such as `widget_await` can receive a decision in the active turn if the client supports that wait. Also provide a scoped result lookup so a click before the wait, a timeout, or reconnect does not lose the result. Return typed decisions for approval, cancellation, and expiry. Verify deadlines and whether the agent continues in each supported client. Consider the MCP Tasks extension only for clients that negotiate it. [MCP Tasks specification](https://tasks.extensions.modelcontextprotocol.io/specification/2026-07-28/tasks) · [Claude Code long tool calls](https://code.claude.com/docs/en/mcp#automatic-backgrounding-of-long-tool-calls)
4. **Close or pin.** Use explicit expiry, operator close, cancellation and successful completion to end the lease. A broken request or bridge may trigger a grace period. Retain just enough of the terminal result to reconcile it without retaining the surface. Pinning creates a durable widget from a supported representation through an explicit PC owner action. The durable widget gets its own identity and permissions.

Target **under 200 ms at the 95th percentile** from accepting a spawn to a usable frame when the app is already running. Measure cold app start, bridge attachment, time from a user decision to client receipt, and cancellation separately. The target is a proposal and the renderer architecture should be chosen from measurements. A successful demo includes clean disposal, late-answer refusal, and one result through a lost reply or host restart.

## Delivery order

1. **Local vertical slice.** Open one diff review or parameter choice with existing renderer primitives, collect a typed result in trusted desktop UI, return it to one tested MCP client, and dispose the surface. Include a packaged macOS check early so the bridge works for a fresh install as well as a source checkout. Follow with a separate pinning check.
2. **Shared controls and authored pages.** Give built-in and authored surfaces the same controls, tokens, and state conventions. Compare one Vercel UI SDK control against the current primitives. If that earns adoption, pin it inside the shell's packaged dependency graph and keep a deepWidgets API for authors. A raw kit Core export requires its own justification. React 19 migration, Direct React authoring, and switching declarative formats each affect separate compatibility contracts. [UI SDK evaluation](widget-interaction-ui-sdk.md)
3. **Richer local collaboration.** Follow the tested workflow with adaptive window modes or typed events between surfaces when a real use case calls for them. Treat desktop context feeds, generic UI inspection and driving, arbitrary code, and bounded sub-agents as separate contributions with distinct authority. A sub-agent lease needs limits, cancellation, and effect ownership. Use trusted confirmation for effects even if an SDK supplies page-local introspection.
4. **Connect compatible hosted providers.** Put the proven action contract behind device-owned grants and a provider-compatible connection. Validate a narrowly scoped read and mutation on one trusted durable widget. Test revocation during restart and receipt lookup after an interrupted write. Keep hosted authoring for the complete permission and execution design. [Provider compatibility and remote acceptance](architecture.md#4-architecture-for-agents-anywhere) · [Permission decision](../widget-system/where-we-stand.md#permission-gaps-standingpermission_gaps)

Vercel's UI SDK launched in public beta on November 12, 2026 and supplies headless behavior primitives. Its optional component bridge is useful for evaluating semantic control operations. The SDK does not define a deepWidgets surface lease, trusted operator decision, provider grant, or host write receipt. `json-render` and shadcn AI Elements may be useful for a later declarative authoring or control decision with a concrete gap.
