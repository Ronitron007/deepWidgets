# Product direction

deepWidgets turns the PC desktop into a local-first, post-app interface runtime where any compatible agent can spawn, inspect, operate, await, compose, and dispose live interactive surfaces and bounded sub-agents under the PC owner's control. A local agent connected over MCP opens an interactive `.tsx` surface in milliseconds, collaborates synchronously with the person at the PC, receives the person's decision in the active workflow, and lets the surface dispose cleanly when its job ends — or lets the person pin it as a durable desktop widget.

Every widget — ephemeral or durable — uses one unified authoring, visual, and operational stack with **no OpenUI DSL (`@openuidev/react-lang`)**. The runtime standardizes on **React 19** and Vercel's **UI SDK** (`@ui-sdk/core` and `@ui-sdk/react`) locked in `@deepwidgets/kit` Core, themed and exported as a ready-made component library through `@deepwidgets/shell/ui/*`, and bridged once per window by `@deepwidgets/widget-kit` (`mountWidget`, `useWidget`, and `@ui-sdk/react/agent`'s `createAgent()`). Durable state and mutations run through host `ctx.widgets` actions, while `interact` mode gains full two-way semantic UI observation and control (`snapshot`, `query`, `act`, and `[data-agent-secret]` redaction) across every widget automatically.

The same provider-neutral MCP and action contracts support later remote connectors from phones and hosted model-provider apps under explicit, revocable per-PC, per-widget, and per-capability grants, once the local loop is proven. See the [unified React 19, UI SDK, and ephemeral surfaces verdict](../explore/reviews/future-of-ui-verdict.md).

## What this means for development

- **Drop OpenUI (`@openuidev/react-lang` and `@openuidev/lang-core`) completely and upgrade to React 19.** Author all built-in, ephemeral, and durable widgets in plain `.tsx` against `useWidget<State, Actions>()` and `@deepwidgets/shell/ui/*` — eliminating custom string DSL syntax, `<Renderer.Root>` wrappers, `CATALOG_ID` gates, and telemetry workarounds.
- **Achieve sub-200 ms warm spawns without a DSL.** Pre-bundle the shared client runtime (`react@19`, `react-dom@19`, `@ui-sdk/core`, `@ui-sdk/react`, `@deepwidgets/shell/ui/*`, `@deepwidgets/widget-kit`) once in Electron via `<script type="importmap">` and compile ephemeral `.tsx` in memory with `esbuild.transform` (~5 ms), bypassing cold Vite builds and `pnpm` installs. Measure warm spawn-to-interactive p95 separately from cold app launch and initial bridge attachment.
- **Ship one uniform component and `interact` spine on Vercel UI SDK.** Lock `react@19`, `react-dom@19`, `@ui-sdk/core`, and `@ui-sdk/react` in `@deepwidgets/kit` Core, theme the 50+ accessible primitives (plus `Trace`, `CodeBlock`, and `Confirmation`) once in `@deepwidgets/shell/ui/*` to insulate widgets from `0.1.0-beta` churn, and mount `createAgent()` inside `@deepwidgets/widget-kit` so `interact` mode can inspect (`snapshot`, `query`) and drive (`act`) live UI controls alongside durable `ctx.widgets` RPCs.
- **Close the human-to-agent loop with durable receipts and trusted authority.** Pair standard `stdio` MCP attachment with `widget_await` and idempotent `decisionId` result lookup across timeouts or reconnects, attach renderer `requestId` values on `POST /call` so pending, committed, failed, and unknown outcomes stay distinct, and enforce consequential approvals and pinning in trusted desktop UI rather than relying on page DOM attributes alone.
- **Keep capabilities explicit and separable.** Treat ephemeral spawning, durable installation, live UI observation, live UI driving, host mutations, screenshots, window modes, desktop context sensors, package additions, and `ctx.effect()`-scoped sub-agents as distinct capabilities governed by the PC owner ([permission-layer design](../explore/widget-system/where-we-stand.md#permission-gaps-standingpermission_gaps)).

## What a unit brief carries

For new or resumed work that changes MCP attachment, React 19 / UI SDK core packages, `.tsx` fast-spawn execution, lifecycle leases, `interact` tools, actions, window authority, startup, update, or packaging, give the implementer and reviewer the unit spec, base revision, and the revision of this direction. State which product rule the unit affects. Older worktrees can read that revision without updating their branch. This applies to an existing session at its next handoff. The unit brief controls which files and behavior the agent may change.

The reviewer checks the affected product rule against the change and its acceptance evidence. An unresolved finding that conflicts with the product direction goes back to the operator for a decision before the unit expands in scope.

## First pilot proposal

Connect a standard MCP client (Cursor or Claude Code) to the desktop app with one `stdio` configuration entry. Have the agent spawn an ephemeral `.tsx` review and parameter-tuning surface built with `@deepwidgets/shell/ui/*` and `useWidget()`, hitting under 200 ms warm spawn-to-interactive at p95 via the pre-bundled React 19 + `@ui-sdk` runtime and in-memory `esbuild.transform`. Verify that `interact` mode can inspect and pre-stage controls via `@deepwidgets/widget-kit`'s `createAgent()` bridge, collect a trusted human decision via `widget_await` with durable `decisionId` lookup across timeout/reconnect, reject late submissions on expired or superseded surfaces, purge ephemeral state on disposal, and promote a chosen surface to a durable widget via Pin across a host restart.
