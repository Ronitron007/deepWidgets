# Plan for the main widget `main_widget.plan`

This plan implements `docs/specs/main-widget.md`. The process is `widget_mvp.plan.process`.

## Units `main_widget.plan.units`

| Unit | Change | Check | Mutant that must fail the check | Needs |
|---|---|---|---|---|
| `main.runtime` | `main_widget.catalog`, and the host half of `main_widget.widget` and `main_widget.widgets`: the built-in slug `main`, the MCP rule, the query of all widgets, Turn off, Turn on, and Remove. | A new host script `tools/widgets-main.mjs` installs a test widget. The `main` query lists `sample` and the test widget with each field of `main_widget.widgets`. `widget_list` does not list `main`, and `widget_call` on `main` gives the error of an unknown slug. Turn off keeps the row in the query with the status turned off, and Turn on brings back the same state. Remove refuses `sample`, and it removes the test widget with its state kept. `GET program` of `sample` gives `catalog` `shadcn-widgets@1`. `tools/widgets-mcp.mjs` and `tools/widgets-create.mjs` pass. | `widget_list` does not filter `main`: the script finds `main` in the list and fails. | none |
| `main.window_state` | `main_widget.window_state`, and the Show and Hide action of `main` | `DSH_SMOKE_WINDOWS=1` also hides `sample` through the action of `main`. The window of `sample` hides, and after a host restart it stays hidden. Show brings it back. Electron main opens no window for `main`. | The host does not store the shown state: after the restart, the window of `sample` shows, and the check fails. | `main.runtime` |
| `main.page` | The page `main.html` with its child and the component set `deepwidgets-main@1`, and the Widgets tab (`main_widget.widgets`) | A new smoke flag `DSH_SMOKE_MAIN=1` loads the page of `main` in a test window. The page shows a row for `sample` with its state rev. A state write of `sample` updates the row. A click on Hide hides the window of `sample`. `DSH_SMOKE_WIDGET=sample` passes. `tools/widget-kit-imports.mjs` passes. | The row does not refresh on a change: the rev in the row stays old, and the check fails. | `main.window_state` |
| `app.menu_bar` | `main_widget.menu_bar` and `main_widget.panel` | `DSH_SMOKE_MAIN=1` also checks that the Dock has no icon and that the menu bar icon exists. A click on the icon opens the panel with the page of `main`, and a loss of focus closes it. A second launch opens the panel. The operator checks by hand that the panel takes focus, and that copy and paste work in it. `DSH_SMOKE_HELLO=1`, `DSH_SMOKE_PROBE=1`, `DSH_SMOKE_TRACE=1`, and `DSH_SMOKE_HOST_RESTART=1` pass. | The panel does not close on a loss of focus: the check fails. | `main.page` |
| `main.settings` | The Settings tab (`main_widget.settings`) without the agents list | `DSH_SMOKE_MAIN=1` also turns off `create` in the Settings tab. Then `widget_install` gives `mode-off`, and the settings file has `"create": false`. The tab shows the port and the path from `mcp.json`. In the dev run, the launch-at-login switch is off with its note, and no login item is registered. A unit test with a stub of `app.setLoginItemSettings` checks that the switch sets the value and shows the status that it reads back. | The switch of `create` writes no file: `widget_install` works, and the check fails. | `main.page` |
| `mcp.agents_list` | The agents section of the Settings tab. The unit stays in `docs/plans/mcp-consent.md`. Its place changes from the main window to the Settings tab. | The check of `mcp.agents_list` in `docs/plans/mcp-consent.md` | The mutant of `mcp.agents_list` | `mcp.consent_dialog`, `main.settings` |

`app.menu_bar` and `main.settings` can run at the same time after `main.page`. Both change the smoke flag `DSH_SMOKE_MAIN`, so the second unit to finish merges the first one in.

The first unit adds `main-widget.md` (`main_widget`) to `head.map` in `CLAUDE.md`. `app.menu_bar` changes the main window row of `head.status`.
