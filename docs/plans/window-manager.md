# Plan for the window manager `window_manager.plan`

This plan implements `docs/specs/window-manager.md`. The process is `widget_mvp.plan.process`.

## Units `window_manager.plan.units`

| Unit | Change | Check | Mutant that must fail the check | Needs |
|---|---|---|---|---|
| `wm.bar` | `window_manager.bar` and `window_manager.move`, with the window data in the memory of Electron main only. The first unit also adds `window-manager.md` to `head.map`, and the shown-state line to `head.status`, in `CLAUDE.md`. | A new smoke flag `DSH_SMOKE_WM=1`. The window of `sample` has the bar view, and the bar is hidden. A hover hook of the check puts the mouse point in the window, and the bar shows. A click of the lock button in the bar view makes `isMovable()` false. A second click makes it true. A click of the layer button makes `isAlwaysOnTop()` false, and a second click makes it true. A drag on the handle moves the window. A drag of a locked window does not move it. The page of `sample` can not reach the bar: a script in the page finds no bar element. `DSH_SMOKE_WINDOWS=1`, `DSH_SMOKE_MAIN=1`, and `DSH_SMOKE_WIDGET=sample` pass. The operator checks by hand that a real drag moves the window, and that the bar shows on hover. | The lock button does not call `setMovable(false)`: `isMovable()` stays true, and the check fails. | none |
| `wm.store` | `window_manager.data`, `window_manager.defaults`, and `window_manager.route`. Electron main writes each operator choice to the route, and obeys the frames.. Also the decisions of 2026-11-28: one default position for both layers, the layer `normal` on one Space (`window_manager.terms`), and the three position fixes of the review of `wm.bar` (`window_manager.move`): `stored_position_not_window_position`, `handle_click_stores_position`, and `native_move_flag_stays_on`. The guide tells agents that the bar covers the top 24 points of the page on hover (`top_strip_of_page_covered`) | First, a run checks that `setVisibleOnAllWorkspaces(false)` keeps a widget window on one Space. If it does not, the unit stops and reports. A new host script `tools/widgets-windows.mjs`. The route sets `layer`, `locked`, and a position for `sample`, and the `hello` frame gives them with `chosen`. After a host restart, the `hello` frame gives the same values. A test widget with `window: { layer: 'normal', width: 400, height: 200, resizable: true }` gets these values in its first `added` frame. A reinstall of it with `width: 500` keeps 400. An agent `widget_remove` and an install keep 400. The Remove of `main` deletes the record, and the next install with `width: 500` gives 500. A size for `sample` gives `not-resizable`. `reset` deletes the position. The route refuses `main`. A call of `/api/widget-windows/sample` from the page of `sample` gets 404. `DSH_SMOKE_WM=1` also checks that after Turn off and Turn on, the new window of `sample` has the stored position, layer, and lock. `widgets-runtime`, `widgets-main`, `widgets-mcp`, `widgets-create`, `widgets-install-replay`, `widgets-action-replay`, and `widgets-crash-replay` pass. `DSH_SMOKE_WM=1` also checks these steps. A click of the layer button does not move the window, also when it is locked. After the click, `isVisibleOnAllWorkspaces()` is false, and after a second click it is true. A drag to the top edge of the display stores the position that `getPosition()` gives. A press and a release on the handle with no move store no position. | A reinstall writes the new agent defaults: the test widget gets 500 after the reinstall, and the check fails. | `wm.bar` |
| `wm.panel` | `window_manager.panel` | `tools/widgets-main.mjs` also checks the actions of the layer, the lock, and the reset. Each one refuses `main` with `unknown-widget`, and a slug with no window with `no-window`. `DSH_SMOKE_MAIN=1` also clicks the layer control of `sample` in the panel, and the window has `isAlwaysOnTop()` false. A click of the lock control makes `isMovable()` false. After a drag, Reset position moves the window to the default position, and the record has no position. A click of the lock button on the bar shows in the row. `tools/widget-kit-imports.mjs` passes. | Reset position keeps the stored position: the window stays, and the check fails. | `wm.store` |
| `wm.tools` | `window_get`, `window_set`, the mode `window`, and its switch in the Settings tab (`window_manager.tools`) | `tools/widgets-mcp.mjs` also checks the tools. `window_get` of `sample` gives the window data. `window_set` of the layer changes the frame. After the route sets the lock, `window_set` of the lock gives `operator-choice` with its next step. A call with the lock and the layer then changes neither one. With `"window": false` in the settings file, `window_set` gives `mode-off`. A size for `sample` gives `not-resizable`. Both tools treat `main` as unknown. `DSH_SMOKE_MAIN=1` also turns `window` off in the Settings tab, and the settings file has `"window": false`. The replays pass. | `window_set` does not check `chosen`: it changes the lock, and the check fails. | `wm.store` |
| `wm.screenshot` | `widget_screenshot` (`window_manager.tools`) | `DSH_SMOKE_WM=1` also calls `widget_screenshot` of `sample` over MCP. The answer is an MCP image of type `image/png`. Its size matches the page of the window, and its pixels are not all the same color. The image does not hold the bar. A window behind another window gives an image too, or the check records that it can not. After the operator Hide, the tool gives `window-hidden` with its next step. The replays pass. | The tool sends an image with no pixels drawn: the color check fails. | `wm.store` |

The order is `wm.bar`, `wm.store`, `wm.panel`, `wm.tools`, and then `wm.screenshot`. The screen comes first. `wm.tools` and `wm.screenshot` can run at the same time after `wm.store`. Both change `tools/smoke-desktop.mjs` or `tools/widgets-mcp.mjs`, so the second unit to finish merges the first one in.

Each unit that changes `deepwidgets/widgets` or `deepwidgets/mcp` runs the install, action, and crash replays. Each unit that changes a file under `widget_state_models.coverage` gets the review of the skill `widget-state-models`.
